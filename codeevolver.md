## ARCHITECTURE TITLE: DSPy ReAct agent over remote ColBERT retriever, scored by set-F1 with GEPA feedback
## ARCHITECTURE SUMMARY:
The program is a three-layer DSPy stack: a pipeline (`PhantomWikiReActPipeline`) that owns infrastructure, a reasoning module (`PhantomWikiReAct`) that owns agent logic, and a counting retriever (`CountingRM`) that wraps a remote ColBERTv2 index. The pipeline wires a DeepSeek-V4-Flash LM (GMI Cloud, `reasoning_effort="high"`) and the retriever into DSPy context on each `forward`, then delegates to the ReAct module, which iteratively calls a `search_wiki` tool (up to 50 iterations, k=7 docs) to answer multi-hop questions over the fictional PhantomWiki corpus. CodeEvolver mutates only `phantomwiki_module.py`; the pipeline and retriever are held fixed. The metric `phantomwiki_f1_feedback` computes set-based F1 over normalized answer lists and returns a `ScoreWithFeedback` carrying textual correct/missed/extra breakdown for the GEPA optimizer.

## ARCHITECTURE DESCRIPTION:
The entry point `PhantomWikiReActPipeline` (src/program/phantomwiki_pipeline.py:18) is a `dspy.Module` that constructs three things in `__init__`: (1) `self.rm = CountingRM(dspy.ColBERTv2(url=COLBERT_URL))` — a retrieval model pointed at a serverless Modal endpoint hosting the PhantomWiki ColBERT index; (2) `self.lm = dspy.LM("openai/deepseek-ai/DeepSeek-V4-Flash", api_base=GMI_API_BASE, reasoning_effort="high", cache=False)` — the reasoning LM routed through GMI Cloud via LiteLLM's OpenAI-compatible interface; (3) `self.program = PhantomWikiReAct()` — the reasoning module. On `forward(question)` it opens `dspy.context(lm=self.lm, rm=self.rm)` and calls `self.program(question=question)`, so the inner module resolves the global LM and retriever from context rather than from explicit attributes.

The reasoning module `PhantomWikiReAct` (src/program/phantomwiki_module.py:4) is what CodeEvolver evolves. It builds a `dspy.Retrieve(k=7)` and a `dspy.ReAct(signature="question -> answer: list[str]", tools=[self.search_wiki], max_iters=50)`. The `search_wiki` tool wraps `dspy.Retrieve`, joining returned passages with double newlines. `forward` runs ReAct and wraps the result as `dspy.Prediction(answer=result.answer)`. Answers are `list[str]` because PhantomWiki questions can require multiple entities (e.g. "list all siblings of X").

`CountingRM` (src/program/counting_rm.py:27) is a `dspy.Retrieve` subclass that thread-safely counts calls (exposed via `call_count`, used by `evaluate.py` to report retrieval cost) and hardens retrieval against the flaky remote index: it monkey-patches ColBERTv2's get-request to use a shared connection-pooled `requests.Session` (pool_maxsize=100), a 240s timeout (vs 10s default) so cold-start scale-ups aren't retried on top of still-running requests, and 2 retries with a 60s backoff on Timeout/ConnectionError.

The metric `phantomwiki_f1_feedback` (src/metric/metric.py:42) is invoked by CodeEvolver's evaluator as `metric_fn(output=program_output, example=Example(row))`. It reads `example.answer` (gold) and `output.answer` (pred), coerces both to lists, normalizes via lowercase+strip, then computes set-based precision/recall/F1 (empty/empty = 1.0, one-side-empty = 0.0). It returns a `dspy.teleprompt.gepa.ScoreWithFeedback` whose `feedback` string records gold/predicted sets (truncated to 1000 chars), the F1 score, and up to 5 correct/missed/extra items — giving the GEPA optimizer per-row signal. A plain-float variant `phantomwiki_f1` (src/metric/metric.py:35) is used by the eval harness `src/evaluate.py`, which runs threaded over train/val/test splits in `data/`, logs F1 by `difficulty`, and totals retrieval calls. `src/tracing_setup.py` auto-instruments DSPy with OpenTelemetry spans on import so the orchestrator can inspect execution traces. Data flow per row: `question -> pipeline.forward -> dspy.context(lm,rm) -> PhantomWikiReAct.forward -> ReAct loop (up to 50) calling search_wiki -> dspy.Retrieve(k=7) -> CountingRM -> remote ColBERTv2 -> passages -> ReAct final `answer: list[str]` -> dspy.Prediction -> phantomwiki_f1_feedback vs gold.answer`.
